# Wi-Fi Control on ESP8266 D1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Version the wiring schematics and protocol, and drive the arm from the laptop over home Wi-Fi with the ESP8266 D1 board. The app discovers the arm on the LAN and uses the same text protocol, safety behaviour and `make`/Docker workflow.

**Architecture:**
- **Firmware:** gains Arduino-free, natively tested network logic (`core/NetCore`): the key check, the discovery reply, and a client session with idle timeout. A thin ESP8266 branch in `roboarm.ino` wires it to `ESP8266WiFi`, mDNS, UDP and TCP. Secrets go from `.env` into a generated, gitignored header.
- **Control app:** gains `TcpLink` (implements the existing `Link`), UDP `discover()`, a tiny `.env` parser shared with `make`, and a "Find arm" button.

**Tech Stack:** arduino-cli + `esp8266:esp8266` core (pinned), C++ (native g++ tests), Python 3.12 stdlib `socket`/`threading`, pytest, Docker, make.

**Spec:** `docs/superpowers/specs/2026-10-18-wifi-esp8266-design.md` (firmware repo)

## Global Constraints

- Work on branch `docker` in both repos: firmware `/home/markunn/Arduino/RoboArm`, control `/home/markunn/Arduino/RoboArmControl`. Never push.
- **Secrets never committed or echoed.** `.env` keys `WIFI_SSID` (1–32 bytes), `WIFI_PASSWORD` (8–63 bytes, printable), `ARM_KEY` (`[A-Za-z0-9_-]{8,40}`). Generated `roboarm/src/boards/wifi_secrets.h` is gitignored. No secret in Docker image layers or build args, and no `--env-file`.
- **Ports:** TCP 3333 (protocol), UDP 3334 (discovery). mDNS host `roboarm` and service `_roboarm._tcp`.
- **Protocol additions:**
  - client's first line `K <ARM_KEY>`; good key → `READY RoboArm`; bad key → `ERR bad key`, closed 1 s later (non-blocking)
  - second client → `ERR busy` + close
  - discovery: request `ROBOARM?`, reply `ROBOARM RoboArm <ip> 3333`
  - USB prints `WIFI <ip>` on connect
- **Timeouts:** the firmware drops a TCP client silent for 10 s and holds position (never detaches). The app heartbeats `?` every 2 s on TCP links. `TcpLink` treats 6 s without received data as disconnected. Connect timeout is 3 s.
- **ESP8266 servo pins:** J1 Claw GPIO13, J2 Wrist GPIO12, J3 Elbow GPIO14, J4 Shoulder GPIO4, J5 Base GPIO5. Never GPIO 0, 2, 15, 1, 3, 16. Limits, home, speeds and homing order are the same as the other boards.
- **FQBN** `esp8266:esp8266:d1`. Core `esp8266:esp8266@3.1.2` from `https://arduino.esp8266.com/stable/package_esp8266com_index.json`. If 3.1.2 is not the latest 3.1.x, pin the latest 3.1.x and record it.
- **`loop()` never blocks.** No `delay()` in the network path.
- **Unchanged:** the ESP32 and Uno builds still compile with unchanged behaviour. Existing tests stay green (firmware 39, control 111).
- **Commit trailer:** `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Wi-Fi unreachable (wrong password, router off).** The firmware keeps retrying, USB control still works, and nothing blocks. Test: F2 `session` tests are time-driven; F3's verification checks the build has no blocking connect loop.
2. **A second laptop/app connects while one is in use.** The second gets `ERR busy` and is closed; the first is unaffected. Test in F2.
3. **The laptop sleeps mid-session (half-open TCP).** The arm drops the silent client after 10 s, holds position, and a new connect works. Tests in F2 (idle expiry) and C1 (6 s receive silence → disconnected).
4. **`.env` with quotes, CRLF, comments, missing or invalid keys.** Clear error naming the key, never the value. Tests in F1 (generator) and C1 (env parser).
5. **Router blocks broadcast.** `discover()` falls back to resolving `roboarm.local` and returns `[]` without raising when nothing answers. The GUI shows the "type its IP" hint. Tests in C2.

**Interfaces — Produces:**
- `discover(timeout: float = 1.0, socket_factory=..., resolver=socket.gethostbyname, broadcasts: list[str] | None = None) -> list[tuple[str, str, int]]`.
  - Sends `b"ROBOARM?"` to every address in `broadcasts`. The default is `["255.255.255.255"] + subnet_broadcasts()`, from parsing `ip -o -4 addr show` (ignore failures).
  - Collects valid replies `ROBOARM <name> <ip> <port>` until the timeout, deduplicated by ip and sorted.
  - If there are none, tries `resolver("roboarm.local")` → `[("RoboArm", ip, 3333)]`.
  - Never raises, and returns `[]` when nothing is found.
- `subnet_broadcasts(ip_output: str | None = None) -> list[str]`: parses `brd` fields and skips 127.x.
- GUI:
  - A "Find arm" button next to the port box, `takefocus=0`. It runs `discover()` in a background thread and posts results to the Tk thread via `root.after`.
  - Results are added as `tcp://<ip>:<port>` entries and the first one is selected.
  - With none, a messagebox: "No arm found — type its IP as tcp://<ip> (shown on USB serial as WIFI <ip>)".
- Makefile:
  - `ARM_KEY` is resolved via `python3 -m roboarm_control.envfile ARM_KEY .env $(ROBOARM_APP_PATH)/.env`, where `ROBOARM_APP_PATH` comes from `.env` by the same parser.
  - `make run-wifi [HOST=…]`: GUI in Docker with `--network host` and `-e ARM_KEY`. It preselects `tcp://$(HOST):3333` when `HOST` is set. No `--device`.
  - With `ARM_KEY` missing, it fails with "ARM_KEY not found in .env or $(ROBOARM_APP_PATH)/.env".
